# Xpeet

iOS app, SwiftUI, iOS 17+, Swift 5. Xcode project is generated by XcodeGen from `project.yml`; never edit `Xpeet.xcodeproj` by hand.

## Commands

- Generate project: `xcodegen generate` (run after adding/removing files or editing `project.yml`)
- Build: `scripts/build.sh`
- Test: `scripts/test.sh`
- Lint: `scripts/lint.sh` (SwiftLint; skipped with a warning if not installed)
- All checks: `scripts/verify.sh`

Healthy output ends with `** BUILD SUCCEEDED **` / `** TEST SUCCEEDED **` and `lint: OK`.

## Verification

Run `scripts/verify.sh` before reporting any task complete, and paste the tail of the output.
If a test fails, fix the code, not the test. Only change a test when the spec/plan says the behavior changes.

## Architecture

Single-screen speedometer: no tabs, no navigation, no networking (see `specs/speedometer/`).

- `Xpeet/App/XpeetApp.swift` entry point; shows `SpeedometerView` directly.
- `Xpeet/Core/Location/` the only code that imports CoreLocation:
  - `SpeedProvider` protocol + `SpeedSample`.
  - `CoreLocationSpeedProvider` (production).
  - `FakeSpeedProvider` (`#if DEBUG`, shared by previews and tests).
- `Xpeet/Features/<Name>/` one folder per feature: `<Name>View.swift` + `<Name>ViewModel.swift`.
  - The ViewModel is `@Observable @MainActor`. Dependencies (provider, `UserDefaults`, `Locale`, clock) are injected through `init` with production defaults.
  - Logic lives in synchronous `handle(...)` methods; `run() async` only feeds streams into them.
  - `Features/Speedometer/Faces/` gauge faces: `GaugeFace` + `Theme` (hex palettes) + pure `GaugeGeometry`; one view per face, laid out by `GaugeDisplay`.
- `XpeetTests/` XCTest unit tests, one file per ViewModel: `<Name>ViewModelTests.swift`; pure helpers may get their own file (e.g. `GaugeGeometryTests.swift`).

## Conventions

- State: Observation framework (`@Observable`, `@State`, `@Bindable`, `@Environment(Type.self)`). No `ObservableObject`/`@Published`.
- ViewModels hold logic and are unit-tested; Views stay declarative with no business logic.
- Concurrency: `async/await`; no Combine, no completion handlers in new code.
- Every View gets a `#Preview`.
- No new third-party dependencies without an approved `plan.md` that says so.

## SDLC workflow

intent (`intent/`) -> spec + plan (`specs/<slug>/`) -> build -> verify -> PR reviewed against `REVIEW.md`.
See `docs/ai-sdlc.md`. When implementation diverges from `plan.md`, update `plan.md` in the same commit.
